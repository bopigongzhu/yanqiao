# 言桥 · E_ShuRu

Windows 11 全拼输入法：把想说的中文变成自然英文，随时展开词句讲解。

**当前构建版本 0.2.5-alpha（2026-10-08）**：候选分页改为固定大小的引用缓存，连续翻页不再累计保存候选文字；新增加密词频副本及损坏恢复，清除时同步清理副本并阻止旧保存写回；完善 ü/v 替代拼写和多音字的词频识别。保留浮窗跟随、高 DPI、主动退出和 7 候选操作。根目录试用脚本指向 `build/0.2.5/x64/bin`，安装版需管理员升级，验证范围见 [优化记录](优化记录.md)。

**切换新版前，请先保存试用文本、关闭旧试用窗口，并从托盘退出旧辅助进程。** 同一登录会话的旧辅助进程会阻止新目录连接。

下文 0.1.0 数据作为首次开发基线保留；最新结果见优化记录。

0.2.5 的 5 分钟浮窗移动／绘制合成测试：辅助进程预热后私有内存 61.34–61.60 MiB，平均 CPU 0.131%（本机 16 逻辑处理器）。完整口径、分页对比及尚待验证的范围见 [资源报告](verification/native-0.2.5/performance.md)。

> 开发版本：0.1.0-alpha · 2026-10-06。「言桥」为暂定名称。已实现并构建 C++ 原生程序、真实全拼引擎、句子缓冲、浮窗、DeepSeek 客户端及 x64 / x86 TSF 组件。目前可在原生试用窗口运行；系统注册、真实 API 与跨应用兼容性尚未验收。

## 直接试用

双击 [启动试用.cmd](启动试用.cmd)，在打开的窗口输入 `nihao`，按空格确认候选，再按 Enter 将整句中文输入文本框。拼音与已选词先留在浮窗里。

- [打开设置.cmd](打开设置.cmd)：在程序里填入自己的 DeepSeek Key，保存后可点“测试连接”。不要把密钥写进源码或发到聊天中。
- `Ctrl+Enter`：输入当前完整英文；需要先确认中文候选，并等待当前句子的翻译完成。
- `Ctrl+J`：按需展开讲解。`Esc`：逐层取消当前拼音、讲解或草稿。
- 托盘图标右键可退出辅助进程。关闭试用窗口后，辅助进程仍可能驻留托盘。

未配置 Key 时，可以完整试用本地中文路径。试用窗口使用真实引擎与进程通信，系统全局输入需要另行注册。详见 [开发进度与运行说明](docs/08-开发进度与运行说明.md)。

精简本地开发包：[EShuRu-0.2.5-alpha.zip](dist/EShuRu-0.2.5-alpha.zip)；解压后运行 `Start-Trial.cmd`。已安装的系统输入法需运行项目 `installer/install.ps1` 升级。安装脚本会把“言桥全拼”加入当前用户的 Windows 键盘列表；若安装时使用了另一个管理员账户，请以日常用户运行一次 `EShuRuMaintenance.exe --register-input`，或打开一次言桥设置完成修复。若旧版退出后重启，可先执行 `build\0.2.5\x64\bin\EShuRuMaintenance.exe --stop-installed` 停用本次会话中的言桥并关闭其安装版辅助进程。

## 构建与检查

在项目目录的 PowerShell 中运行（需要 Python 3.12+、网络和 Windows 自带 tar）：

```powershell
python tools/bootstrap.py
python tools/build.py
python tools/verify.py
python tools/package.py
```

工具链位于项目内 `.tools`，不会全局安装。安装脚本位于 `installer`，需管理员 PowerShell；本轮没有修改系统输入法注册或默认输入法。安装或切换异常时，运行 `EShuRuMaintenance.exe --doctor` 可只读检查文件、COM 注册、当前用户键盘列表和活动输入法状态。

本地检查已通过：181 项核心断言、18 项进程集成检查、5 项原生试用输入检查、32 次管道取消循环，以及 x64 / x86 安全模式 TSF 生命周期测试。原始报告在 [verification/native](verification/native/summary.json)。这些检查不代替记事本、Edge、微信等真实宿主的系统输入测试。

无界面辅助进程的初步实测：约 **4.01 MiB 私有内存 / 16.68 MiB 工作集**。16 逻辑处理器上 10 秒空闲采样未记录到 CPU 时间增量；不代表永远占用 0%，也不包括实际宿主、绘制界面和联网负载。完整性能目标仍待验证。

## 已锁定的产品边界

- Windows 11 系统输入法；面向自己和少量朋友，后续才评估安卓。
- 全拼，交互习惯接近微软拼音；中文候选与英文区域同时存在。
- 在输入法内组织中文句子，确认后才将中文或英文送入当前软件。
- 持续打字时定期更新英文，每次只给一个自然表达。
- 重点学习母语者常用表达；允许俚语和较难句型，不刻意复杂化。
- 中文讲解按需展开，包含重点词、短语、可套用句型和少量例句。
- DeepSeek 为首选服务，每人使用自己的 API Key、承担自己的费用。
- **不做练习记录、收藏、朗读，也不规划这些功能的后续入口。**

## 开发时先处理什么

接下来验证系统注册后的「原生输入与焦点」及「DeepSeek 延迟与质量」两条关键路径。API 请求发出到完整可用翻译的目标为 **1 秒以内**；该目标没有经过实测，不能用模拟动画、首 token 时间或平均值替代完整结果的验收。中文输入必须始终独立于网络正常工作。

工程默认项（如 x64 优先、快捷键、颜色、刷新间隔）已经给出可执行建议，统一记录于决策文档；它们不是需求访谈中用户逐项确认的硬性要求。

用户补充要求资源优化后，原生界面成为首选方案。建议预算为单应用活跃总增量私有内存不超过 120 MiB，3 个已启用宿主合计不超过 180 MiB；8 逻辑处理器参考机上空闲平均 CPU 不超过 0.1%，连续翻译平均不超过 2%。**这些是待验证的预算，不是已测占用。** 详细口径见第 7 份文档。
