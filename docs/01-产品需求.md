# 01 · 产品需求

版本 0.1 · 2026-10-05 · 状态：可进入技术验证与原型开发。

## 1. 产品目标

做一个真正注册到 Windows 的全拼输入法。用户用熟悉的全拼输入想说的中文，在输入法的句子编辑区逐词组织、修改；同时看到一条自然的英语口语表达，按需理解其中的词句，最后主动选择输入中文或英文。

主要用户能看懂一些日常英文，但难以自己组织表达。产品帮助用户把自己的表达意图与英语说法联系起来。翻译质量不能只以逐字对应评估，应同时保留语义、态度、语气与使用场合。

## 2. 已确认需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| R01 | Windows 11 系统输入法，能在常用软件的文本控件中使用 | 必须 |

| R03 | 句子留在输入法中组织，不先进入宿主文本再替换 | 必须 |
| R04 | 中文候选区与英文翻译区共同展示 | 必须 |
| R05 | 持续输入也定期更新英文，不以停止输入为唯一触发条件 | 必须 |
| R06 | 只展示一个英文表达，不提供多候选翻译列表 | 必须 |
| R07 | 采用自然的母语者口语，可有俚语和较难句型 | 必须 |
| R08 | 讲解默认收起，点击或快捷键展开 | 必须 |

## 3. 一次完整使用流程

1. 用户通过 Windows 输入法切换功能启用言桥，在目标软件文本框中开始输入全拼。
2. 拼音和中文候选由本地引擎提供，不等待网络。用空格或数字选词后，词语进入输入法的句子编辑区。
3. 句子编辑区积累整句中文；目标文本框暂不增加这些文字。
4. 中文内容变化后，调度器定期翻译当前快照；用户仍可继续输入、选择候选和修改中文。
5. 英文区显示一条表达。刷新过程中保留可读内容并标明“更新中”；较旧版本不能输入到目标软件。
6. 用户需要学习时展开“词句讲解”。讲解针对显示的当前完整英文，内容默认精简。
7. 用户点击“输入中文”或按 Enter，将中文整句输入目标软件；点击“输入英文”或按 Ctrl+Enter，输入当前有效英文。
8. 输入成功后清空本次草稿和讲解，关闭浮窗。不会继续替用户按发送键，不建立历史记录。

本文件中的“输入到目标软件”指插入文字，不等于聊天软件的“发送消息”。

## 4. 全拼与句子编辑

- 全拼候选是本地、即时的；每页默认 5 个，支持翻页、标点、数字、退格和光标移动。
- 句子编辑区由已选中文字和可能存在的拼音组合段构成。未确认的候选预览使用下划线区分。
- 当前拼音存在时，空格 / 数字只做选词，不提交整句。标点只进入句子缓冲，也不自动提交。
- 没有拼音组合时，数字作为数字输入，空格在缓冲中插入空格。
- 句子内点击定位不应夺走宿主输入焦点，文字编辑由输入服务统一处理。
- 可以通过明确操作取消草稿；切换目标文本上下文时，不将旧草稿自动输入到新位置。
- 工程默认单次草稿上限为 300 个 Unicode 字符；达到上限给出就近提示。超长内容、粘贴、混合文本均须测试。
- Windows 自带的输入法切换能力保留；新输入法不复用或修改微软拼音的私有词库。

## 5. 翻译与讲解质量

### 翻译

- 意思、时间、否定、人物、数量必须保持；不可自行补充事实。
- 默认自然、通用的日常口语；优先美式常见拼写作为设计默认，不强行加入地域俚语。
- 根据原句判断语气；正式内容不故意口语化到失礼。
- 一条表达可以有两个自然短句，但不能输出多个备选、编号、标题或中文讲解。
- 对正在变化的片段允许给出片段翻译；不可把缺失部分编成完整事件。
- 中文歧义无法消除时，选择普通语境下合理的说法，不能承诺准确还原未提供的语境。

### 讲解

基准例句：

> 中文：我今天累坏了，想早点睡。  
> 英文：I'm beat. I think I'll turn in early tonight.

展开内容：

- **I'm beat**：我累坏了，常见的非正式口语表达。
- **turn in**：这里指上床睡觉；turn in early 表示早点睡。
- **I think I'll…**：表达当下打算。例：I think I'll take a break.（我想休息一下。）

每次最多 3 个讲解项、通常 1 个英文例句及中文释义。没有必要讲 3 点时可更少。讲解必须对应当前英文，不借机推荐朗读、收藏、复习或练习记录。

## 6. 数据与费用

- 只发送本次主动输入的中文快照；请求讲解时附带本次对应英文。
- 不读取聊天历史、整篇文档、剪贴板背景内容或其他应用的输入。
- API Key 保存在 Windows 凭据存储中；不写入普通配置文件、日志、安装包或代码仓库。
- 客户端不持久化句子、翻译、讲解；短期内存状态仅服务于当前输入会话。
- 默认关闭会写入完整输入内容的引擎学习、用户词库扩展及调试日志；确需保留词频时另行审查，不与“不保留内容”的默认规则混用。
- 每人自行承担 DeepSeek 账单，没有统一转发计费服务，也没有产品账号体系。
- 暂未确认月度预算硬上限，不擅自设置充值或付费额度。
- 服务商自身的数据处理政策由服务商决定；“客户端不保存”不能写成“云端绝不保存”。

## 7. 本次范围以外

不开发安卓版本、语音输入、录音、跟读评分、朗读、练习记录、收藏、生词本、复习提醒、聊天机器人、英语作文纠错、整页翻译、多翻译候选、账号和云同步、好友功能。除安卓已有后续意向外，这些不自动进入未来路线图。

## 8. 正常降级

| 情况 | 用户可继续做什么 | 界面反馈 |
|---|---|---|
| 没配置 Key | 全拼、选词、编辑、输入中文 | 英文区显示“连接 DeepSeek 后显示英文” |
| 断网 / 超时 | 正常输入中文；手动重试翻译 | 保留草稿，显示“暂时无法翻译” |
| Key 无效 / 余额不足 | 正常输入中文；打开设置处理 | 明确区分凭据错误和余额问题 |
| 翻译未完成 / 已过期 | 继续编辑中文、提交中文 | 英文可阅读，但“输入英文”不可用 |
| 讲解失败 | 使用已经有效的英文 | 仅讲解面板显示重试入口 |
| 浮窗服务崩溃 | 宿主不崩溃；草稿可用 Enter 输入中文，或 Esc 取消 | 自动尝试恢复浮窗；无法显示候选时不继续吞入新拼音 |
| 密码或安全输入场景 | 采用系统允许的直接输入方式 | 不显示翻译，不向网络发送输入 |

## 9. 设计默认项

暂定产品名“言桥”，Windows 11 x64 优先，同时验证 x86 宿主；默认浅色并可随系统切换；编辑区默认上限 300 字；Enter 输入中文，Ctrl+Enter 输入英文，Ctrl+J 展开讲解。上述为工程与界面方案，后续可以调整，不改变已确认的产品目标。
