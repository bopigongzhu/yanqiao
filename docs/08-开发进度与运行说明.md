## 2. 立即运行

项目目录：`D:\尝试\E_ShuRu`。

1. 双击根目录 `启动试用.cmd`。
2. 等状态显示全拼引擎已连接，在文本框输入 `nihao`。
3. 按空格或数字确认中文。此时目标文本框仍然为空，中文位于浮窗。
4. 按 Enter，整句中文进入文本框，不额外模拟回车。
5. 若需要翻译，先打开设置，输入个人 Key 并保存。测试连接会发送固定短句“你好。”，产生少量 API 用量；正常打字时会向 DeepSeek 发送当前草稿快照。
6. 完整英文出现、且候选已确认后，按 Ctrl+Enter 输入英文。按 Ctrl+J 展开当前英文的讲解。

Key 不配置时，本地中文仍可运行。程序不内置共享账号，不会给出伪装成实时翻译的示例英文。

| 操作 | 行为 |
|---|---|
| 字母全拼、空格 / 1–5 | 拼音输入、选择候选进入内部句子 |
| Enter | 接受当前候选并输入整句中文 |
| Ctrl+Enter | 仅输入当前已验证的完整英文 |
| Ctrl+J | 展开 / 收起当前英文讲解 |
| Esc | 先取消拼音，再收起讲解，最后清空草稿 |
| 单独 Shift | 无活动草稿时切换中 / 英模式 |
| ← / →、Home / End | 编辑内部光标或当前拼音位置 |
| PageUp / PageDown | 有拼音时翻候选页 |

失焦会取消当前草稿。试用窗口关闭后辅助进程可继续留在托盘，双击托盘图标打开设置，右键“退出辅助进程”结束。

同一 Windows 登录会话只允许一个辅助进程。试用目录和安装目录具有不同的进程路径校验：从便携试用切换到系统安装版前，先从托盘退出旧辅助进程。

已生成精简本地开发包：[EShuRu-0.1.0-alpha.zip](../dist/EShuRu-0.1.0-alpha.zip)，约 5.3 MiB。解压后双击 `Start-Trial.cmd`；也可直接运行 [打包目录中的启动脚本](../dist/EShuRu-0.1.0-alpha/Start-Trial.cmd)。包只包含运行文件、词典、安装脚本和许可说明，不含编译器、测试工具或个人配置。文件哈希与 ZIP 完整性已检查，打包目录中的 5 项原生输入检查再次通过，见 [package-ui.json](../verification/native/package-ui.json)。

## 3. 系统安装与卸载

本轮运行环境没有管理员令牌，因此**没有调用 regsvr32 注册输入法**。这些步骤是供后续实际验证的安装操作，不能据此认定全局输入已正常工作。

在 **64 位管理员 PowerShell** 中：

```powershell
Set-Location 'D:\尝试\E_ShuRu'
& .\installer\install.ps1
```

脚本将运行文件复制到 `%ProgramFiles%\EShuRu`，分别使用 System32 / SysWOW64 的 regsvr32 注册 64 / 32 位组件。若第二步失败，会尝试撤销 64 位注册，并保留文件用于排查。脚本不切换系统默认输入法、不添加自动登录启动项。

之后通过 Win+Space 查找“言桥全拼”。若输入列表未刷新，注销并重新登录，在“设置 → 时间和语言 → 语言和区域 → 中文 → 语言选项 → 键盘”检查。优先在空白记事本与测试网页验证，不把它视为已通过微信、Word 等应用验收。

此 Alpha 尚未签名。如本机策略禁止执行脚本，应按本机策略处理；项目不会自动降低 PowerShell 执行策略。

注销输入法：

```powershell
& .\installer\uninstall.ps1
```

默认只注销并保留安装文件。退出辅助进程、关闭加载过该输入法的应用后，可以用 `-RemoveFiles` 一并移除固定安装目录。若 DLL 仍被占用，脚本会报告失败，注销登录后再清理。

卸载脚本保留当前用户的外观设置与 Key，避免管理员身份切换时误操作用户凭据。需要移除 Key 时，在卸载前点设置中的“删除密钥”，或在本用户 Windows 凭据管理器删除 `EShuRu/DeepSeek`。

## 4. 实际代码结构

```text
src/tsf.cpp             x64 / x86 宿主中的轻量 TSF 桥接
src/ipc.*              双向命名管道、身份与协议检查、有界队列
src/rime_engine.*      单辅助进程内的共享全拼引擎
src/core.*             句子、内容版本、SSE、输出校验
src/app.*              会话路由、调度、提交握手、托盘
src/ai.*               DeepSeek 请求与后台工作线程
src/panel.*            原生浮窗、设置窗口、渲染预览
src/sandbox.*          不安装输入法即可运行的原生试用窗口
tests/                 核心、进程集成、安全生命周期、管道取消
tools/                 依赖准备、构建、检查、打包
installer/             管理员安装 / 注销脚本
verification/native/   自动检查原始报告和源码哈希
```

实际架构采用**单辅助进程集中持有 Rime、草稿、界面与网络**。每个宿主仅加载对应位数的 TSF 桥接 DLL；不会在每个宿主重复初始化词典。宿主按键入有界队列，工作线程负责 IPC，最终插入回到宿主的 TSF 编辑会话。

这也有明确代价：辅助进程退出后，当前未提交草稿会丢失。桥接停止接收拼音，切换输入法 / 重新打开试用窗口后恢复；自动重连和草稿容错尚未完成。

网络使用 WinHTTP 同步调用，但只发生在两个独立后台工作线程（翻译 / 讲解）中，不阻塞键盘和界面线程。取消使旧结果失效，不保证立即终止正在阻塞的 WinHTTP 调用。读取超时为 6 秒；另有请求处理时长检查，**不是严格 6 秒端到端截止**。

## 6. 已测性能与目标的区别

环境：Windows 11 家庭中文版，10.0.26200；AMD Ryzen 7 5800H，16 逻辑处理器；系统报告可用物理内存约 13.86 GiB。Release 构建，未连接 API。

| 范围 | 实测 |
|---|---|
| 核心测试进程，含真实 Rime | Private Bytes 2.61 MiB；Working Set 12.21 MiB |
| 合成引擎循环 200 次 | 平均 0.054 ms / 循环，仅引擎操作，不是按键到屏幕延迟 |
| 已初始化的无界面辅助进程 | Private Bytes 4.01 MiB；Working Set 16.68 MiB |
| 无界面辅助进程空闲 10.02 秒 | 进程 CPU 时间计数无增量，整机归一化样本为 0.0% |

这组数字不能相加推导整套产品成本，也不代表日常使用固定占用。尚缺：绘制浮窗与设置的稳定占用、实际宿主 DLL 增量、3 宿主并存、真实流式翻译与讲解、8 小时耐久及句柄增长、按键端到端 p95。短时间 CPU 计数为 0 只反映该次采样精度下的结果。

已落实的优化：一个词典实例、原生 UI 无浏览器运行时、空闲事件等待、最短 500ms 翻译间隔、只保留一个最新待发快照、流式 UI 50ms 合并、有界 IPC、词典预编译、无历史数据库。正式目标仍按 [第 7 份文档](07-性能预算与优化.md) 验收：单宿主活跃总增量私有内存 ≤120 MiB，3 宿主 ≤180 MiB；8 逻辑处理器参考机空闲平均 CPU ≤0.1%、连续翻译 ≤2%。
